# 仕様: 扉 — index

## 構成ファイル

```dataview
LIST
WHERE file.folder = this.file.folder AND file.name != this.file.name
SORT file.name ASC
```

---

## 境界判定テーブル

どのファイルに何を書くかの判定基準。**1記述＝1行き先**で迷いなく決まる。

| 記述の種類 | テスト | 行き先 |
|---|---|---|
| 内部状態・ルール | 画面/音/操作を消しても残る規則か？ | `040.020.仕様` |
| 知覚・操作する出力 | 感覚器官への出力（見た目・音・操作感）か？ | `040.030.演出・UI` |
| 技術的な作り方 | 「どう実現するか」の話か？ | `040.040.実装` |
| 定義・目的 | — | `040.020.仕様` 冒頭「概要・目的」が唯一の正典 |
| 未決事項 | — | 各ファイルの `> 未決`（現行踏襲） |

---

## 運用フロー

1. **人間**は `040.010.ラフ` のみ編集（追加・変更はすべてここ）
2. **AI** がラフから `040.020 / 040.030 / 040.040` を生成・更新（変化した観点だけ再生成）
3. 出力ファイル（020/030/040）は直接触らない。直すならラフへ戻す
4. 演出・UI や実装が **無い** 仕様は該当ファイルを生成しない（空ファイルを残さない）
