# ファイル命名・ディレクトリ規約

Colours プロジェクトのドキュメント（Vault 内）に適用する命名・構成ルール。
コード/アセットの命名は対象外（→ [[コーディング規約]] / [[アセット命名規約]]）。

---

## 1. 基本方針

- **「読み順・優先順に意味があり、項目が増えていく」カテゴリは番号を振る**（例: 仕様、実装ステップ、ステージ）。
- **辞書的に名前で引くもの・固有名・時系列ログは番号を振らない**（例: 規約集、人物ページ、日次ログ）。
- 1ディレクトリ＝1カテゴリ。階層はディレクトリで表現する。
- `_` プレフィックスは**禁止**。番号または内容を表す名前を使う。

---

## 2. 番号フォーマット（番号を振るカテゴリ）

- **3桁**。1の位はバッファとして `0` 固定 → `010, 020, 030 …`（10刻み。間に挿入余地を残す）。
- 100 を超える規模になったら、それはカテゴリ分割のサイン → サブディレクトリを切る。
- **階層は番号を連結**：子は `[親番号].[自番号]`（例: `030.010.010_懐中電灯`）。全階層を連結し、ファイル名単体でグローバルに一意・ソート可能にする。
- **ディレクトリの概要ファイル（フォルダノート）は `000_概要.md`** で統一。
- 区切り文字：番号と名前の間は `_`（アンダースコア）、階層番号間は `.`（ドット）。

**例**
```
仕様/
  000_概要.md               ← 仕様ディレクトリの索引
  010_混色システム.md
  020_プレイヤー/
    000_概要.md              ← フォルダノート（共通名）
    020.010_モノを拾う.md
  030_ギミック/
    030.010_ライト/
      000_概要.md            ← フォルダノート
      030.010.010_懐中電灯.md
      030.010.020_サーチライト.md
```

---

## 3. 特殊ファイル

### テンプレートファイル
- 雛形：`[名前]_template.md`
- input 雛形：`[名前]_input_template.md`
- テンプレートディレクトリ：`template/`（`_template` 廃止）
- 新規作成時にコピーして使う。中身を直接編集しない。

### input / output 2ファイル運用
確定文書（Claude整形）とラフ（ユーザー記入）を分離する。

| 種別 | ファイル名 | 誰が書くか |
|---|---|---|
| output（確定） | `[名前].md` | Claude が整形 |
| input（ラフ） | `[名前]_input.md` | ユーザーが気軽に |

### 日付サフィックス
時系列で量産されるログは `[名前]_YYYYMMDD.md`（番号は振らない）。

---

## 4. ディレクトリ別 適用方針

| ディレクトリ | 番号 | 命名ルール |
|---|---|---|
| `仕様/` | ◯ | 3桁階層連番。フォルダノートは `000_概要.md` |
| `実装ログ/` | △ | 機能 dir は固有名。内部ステップは `010_/020_…`（3桁） |
| `level_design/` | ◯ | ステージは `010_Stage1/`、プロトタイプは `000_プロトタイプ/` 等 |
| `規約/` | ✕ | 内容を表す名前（`〜規約.md` `〜フロー.md`） |
| `個人ページ/` | ✕ | 人名ディレクトリ。テンプレートは `template/` |
| `個人計画/` | ✕ | 索引・計画は名前、日次/週次ログは日付サフィックス |
| `shared/` 直下 | ✕ | 内容を表す名前（`現在地.md`, `構造マップ.md` 等） |

---

## 5. 改名の手順

リネームは手動編集せず**スクリプトで一括変換**し、wikiリンク・パス参照も同時更新する。
実施後は git＋Diversion 両方へコミット。

> 実績：`shared/仕様/` の命名規則統一（2026-06-24 / commit `1c7b697`）
