# 実行計画: 仕様策定フローの組み込み

## 背景・問題

仕様策定（ラフ記入→エージェントレビュー→完了）という作業ステップが：
- Jiraチケットとして管理されていない
- `要チケット化リスト.md` に仕様策定カテゴリが存在しない
- `起動ガイド.md` に仕様策定セッションモードのエントリーがない
- `ゲーム開発アシスタント.md` の企画モードが「Jira起票で終わり」になっており、仕様ファイル整備ステップがない

## 完了定義

ユーザーが `.010.ラフ.md` を記入し、エージェントのレビューを通過した状態。

## トリガー（仕様策定タスクが積まれる条件）

1. 新機能・ギミックが決まった時
2. マイルストーン計画セッション開始時

## Task 2: 仕様策定レビュー手順を仕様規約に追記する

**対象ファイル**: `D:\document\ObsidianVault\創作\ゲーム\Colours\shared\050.仕様\050.001.テンプレート\001.001.仕様規約.md`

**作業内容**:
現行の「運用フロー」セクション（4ステップ）に、以下のレビューステップを追記する：

```
3. ユーザーがラフを記入したら「このラフをレビューして」と依頼する
4. AI は以下の観点でレビューし、問題があれば差し戻す：
   - 既存の確定事項（決定ログ）との論理矛盾がないか
   - 実装着手に必要な判断が全て記述されているか
   - 未決事項欄に残っている論点が着手前に確定できるか
5. レビュー通過後、AI が 020.仕様 / 030.演出・UI / 040.実装 を生成する
6. 対応するSPチケットを完了にする
```

現行の「3. 出力ファイルは直接触らない」以降は 7 以降に繰り下げる。

**完了条件**: レビュー基準が明文化され、エージェントが判定できる状態になる

## Task 3: 起動ガイドに仕様策定セッションモードを追加する

**対象ファイル**: `D:\document\ObsidianVault\AI\Instructions\起動ガイド.md`

**作業内容**:
タスク別一覧テーブルに以下の行を追加する：

| タスク | 読み込むファイル | 推奨モデル |
|--------|----------------|-----------|
| 仕様策定・マイルストーン計画 | `ゲーム開発アシスタント.md` → `要チケット化リスト.md`（SPカテゴリ） → 対象仕様の `010.ラフ.md` | Opus |

**セッション開始時の動作**（テーブル下に注記として追加）:
- 起動時に `要チケット化リスト.md` のSPカテゴリを読み、未完チケット（ラフ未記入・レビュー未済）を一覧表示する
- ユーザーに「どのSPチケットを進めるか」を選ばせる
- ラフ記入済みであればレビューへ、未記入なら記入をサポートする

**完了条件**: 起動ガイドを見れば仕様策定セッションの始め方がわかる

## Task 4: ゲーム開発アシスタントの企画モードに仕様策定ステップを追加する

**対象ファイル**: `D:\document\ObsidianVault\創作\ゲーム\Colours\個人計画\ゲーム開発アシスタント.md`

**作業内容**:
`Session Mid（企画モード）` セクションの末尾に以下を追加する：

```markdown
### 仕様策定チェック（企画モード時・常時）

- **新機能・ギミックの決定が出た場合**:
  1. 対応する `050.仕様/` のラフファイルが存在するか確認する
  2. 存在しなければ仕様ファイル群を `050.001.テンプレート/` からコピーして作成し、
     SPチケットを `要チケット化リスト.md` インボックスに追加する

- **マイルストーン計画セッション開始時**:
  1. `要チケット化リスト.md` の SP カテゴリを読み、未完チケットを一覧表示する
  2. 未完チケットを今週・今月の企画日タスクに展開する提案を行う
```

**完了条件**: 企画セッションで機能決定 → 仕様策定タスク追加が自動的に促される

## Task 5: 現在の未完仕様策定タスクをJiraへ起票する

**前提**: Task 1 完了（SPカテゴリ表が存在すること）

**作業内容**:
1. `要チケット化リスト.md` の SP カテゴリを Jira MCP 経由で起票する
2. 各SPチケットに対応する実装チケット（CS-1等）を「ブロック元」としてリンクする
3. `要チケット化リスト.md` の SP 表をJira起票済みとしてマークする

**起票フォーマット**:
- Summary: `[SP-N] <仕様名> 仕様策定`
- Description: 対象ファイルパス・レビュー基準・対応実装チケットID
- Label: `分類:仕様策定`
- 依存: 対応実装チケットを「is blocked by」でリンク

**完了条件**: JiraボードでどのSPチケットがどの実装チケットをブロックしているかが見える
