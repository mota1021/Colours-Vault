# Jiraチケットスナップショット — 実行計画

## 目的

Jira (SCRUM) をタスク状態の単一マスターとし、AIが軽量に読める Markdown スナップショットを生成する。

## 識別ルール

- **一意識別子**: Jiraキー（例: `SCRUM-73`）。
- **人間向け名称**: Jira summary 由来の表示名。歴史的な `[SP-N]` 先頭prefixだけ表示上除去する。
- 旧独自IDラベルやカテゴリ略号を識別子として使用しない。
- `元ID:*` ラベルが存在していても無視し、欠けていても処理を止めない。

## 生成物

`shared/900.AIエージェント用/チケットスナップショット.md`

列は `Jiraキー / 名称 / 状態 / カテゴリ / 担当 / 後続チケット / 先行チケット / 着手開始日`。
`着手開始日` のみユーザー管理値として既存スナップショットから Jiraキーで引き継ぐ。それ以外は毎回 Jira から再生成する。

## 実行

`shared/.vault-data/900.AIエージェント用/scripts/jira_sp_snapshot.py` を実行する。
現行マイルストーンは `.env` の `CURRENT_MILESTONE_EPIC` を使用する。

## 完了条件

- 現行マイルストーンのチケットが Jiraキーと意味名で一覧化される。
- 旧独自IDラベルの有無でチケットが欠落しない。
- 既存の着手開始日が維持される。
- APIエラーや0件取得は明示的に異常終了する。
