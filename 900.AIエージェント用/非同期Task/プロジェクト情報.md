## UEColours ミラー同期ルール

GitHub `UEColours` を使う目的は、チャットやコードエージェントからテキスト実装を操作できるようにすること。Diversion と GitHub を独立した2つの正本として運用しない。

- **作業前**: GitHubで実装を始める前に、GitHub側の対象ファイルが Diversion `main` の現行内容と同期していることを確認する。少なくとも今回変更する `Source/`、必要に応じて `Config/`、`Colours.uproject` を比較対象にする。
- Diversion側を確認できない環境では、GitHub側を無条件に最新版とみなさない。同期未確認であることを明示し、Diversion側との差分確認を次の必須アクションとして残す。
- **GitHub作業中**: PR・レビュー・AI実装は `UEColours` で行ってよい。GitHub上のマージは「AI側の変更確定」であり、チーム実装への反映完了を意味しない。
- **作業後**: GitHubで確定した変更を `E:\UEProjects\Colours` へ反映し、必要なビルド・PIE確認を行ったうえで Diversion にcommitする。ここまで済んで初めてチーム実装へ反映済みと扱う。
- **差分が衝突した場合**: Diversionをチーム側の基準状態として扱うが、GitHub側の意図した変更を単純に破棄・上書きしない。双方の差分を比較し、必要な変更を統合してから両側を同じ内容へ揃える。
- **逆方向の変更**: UE Editor作業等で Diversion 側の `Source/`・`Config/`・`.uproject` が先に変更された場合、次にGitHubでAI作業を行う前に `UEColours` へ反映する。
- ヒルタ側に GitHub 運用を要求しない。チーム共有は引き続き Diversion を介する。
