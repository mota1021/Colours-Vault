# 光の多ホップ伝播 — 実装計画

## 目的

SCRUM-73で完成した `AColoursLightSourceBase` の「Bounds→候補点→形状判定→光値通知」に、**遮蔽判定とガラス透過による色搬送**を追加する。

Stage1では反射・屈折を行わないため、旧計画の「ガラス出射面から継続レイを再発射する多ホップループ」は採用しない。UE標準のMulti Traceで候補点までの直線上にある複数ガラスをまとめて取得し、順番に色フィルタを適用する。

---

## 設計原則

- Unreal Engine標準機能で足りる箇所は標準機能を使う。
- 現在必要な機能だけを作る。
- 専用Propagation Component、透過Interface、出射点API、再帰伝播基盤は作らない。
- 新しい公開Gameplay APIは増やさない。
- 既存Coneの見た目・断面表示は回帰させない。

---

## 最終アーキテクチャ

```text
AColoursLightSourceBase
  ├─ GetLightBounds()         : 候補Actorを絞る
  ├─ IsPointLit(Point)        : 形状内か判定
  ├─ GetLightValueAt(Point)   : 元のFColoursLightValue
  │
  └─ ResolveLightAtPoint()    : 新規・内部処理
       ├─ LineTraceMultiByChannel
       ├─ 遮蔽物を判定
       ├─ AColoursGlassのOverlapを手前から処理
       └─ 透過後FColoursLightValueを返す

AErasableWall
  └─ ApplyLightToSegment(Index, bLit, LightValue)
```

伝播処理は `AColoursLightSourceBase` 内部へ置く。現時点では独立Componentにする実利がない。

## Collision設計

### 既存チャンネルを流用しない理由

`ECC_GameTraceChannel2` は現状、Cone断面表示用として次の特殊な使い方をしている。

- `AErasableWall::DetectionBox` = Block
- `AErasableWall::Segment` = Ignore

このまま可視性判定に使うと、消去済みの穴でもDetectionBoxに遮られ、穴の向こうへ光が届かない。

そのため、**光のGameplay可視性専用Trace Channelを1本だけ追加する**。

### 新チャンネルのResponse

| 対象 | Response |
|---|---|
| 通常の遮蔽物 | Block |
| `AErasableWall` 有効Segment | Block |
| `AErasableWall` DetectionBox | Ignore |
| 消去済みSegment | Collision無効 |
| `AColoursGlass` | Overlap |
| Character / Pawn | Ignore |

候補点自身のActorはTrace QueryでIgnoreする。これにより、対象セルが既に消えてCollisionが無い状態でも照射状態が安定する。

---

## 可視性・色搬送フロー

`AColoursLightSourceBase::UpdateErasableWalls()` のセル処理を次の順序にする。

1. `IsPointLit(CellCenter)` がfalseなら非照射。
2. `GetLightValueAt(CellCenter)` で元の光値を取得。
3. 光源位置から `CellCenter` へ `LineTraceMultiByChannel`。
4. 対象Actor自身・光源自身・Characterは無視。
5. Trace結果を距離順に処理。
6. `AColoursGlass` のOverlapなら透過率を光値へ適用して続行。
7. ガラス以外のBlockが候補点より手前にあれば非照射。
8. RGBが黒、または `Intensity <= 0` なら非照射。
9. 遮蔽されず光が残っていれば、透過後 `FColoursLightValue` を `ApplyLightToSegment()` へ渡す。

候補Actor自身は最初からIgnoreしているため、「対象Actorへヒットしたか」は到達条件にしない。候補点までに別のBlockが無ければ到達と判断する。

## ガラス

### 最小実装

実装開始時点で具体ガラスクラスが無い場合、SCRUM-72のE2E検証に必要な範囲だけ `AColoursGlass` を追加する。

必要なのは次だけ。

- Collisionを持つ
- プレイヤーに対しては壁としてBlock
- Light Visibility ChannelにはOverlap
- `Transmittance (T_R,T_G,T_B)` をEditAnywhereで保持
- 入射 `FColoursLightValue` に透過率を適用する小さな関数

以下はSCRUM-72では作らない。

- ガラス用汎用Interface
- 出射点計算
- 屈折
- 反射
- 専用Propagation Component
- ガラス演出・完成アセット

### 透過計算

入射RGBを `(R,G,B)`、透過率を `(T_R,T_G,T_B)` とする。

```text
P = (R*T_R, G*T_G, B*T_B)
M = max(P_R, P_G, P_B)

M ≈ 0:
    RGB' = (0,0,0)
otherwise:
    RGB' = round(255 * P / M)
```

`Intensity` と `DamageValue` は変更しない。

複数ガラスは手前から順にこの変換を適用する。

## 既存ConeTraceの扱い

`AColoursConeLight::PerformConeTrace()` に残っている `NumTraces` 本の扇状Traceは、SCRUM-73で既存断面表示を保つための**視覚フォールバック**として残す。

SCRUM-72以降、セル消去や色搬送のGameplay判定には使用しない。

このTaskで無理に削除しない。削除には断面可視性の代替判定が必要になり、今回の受け入れ条件を超えるため。

## 実装ステップ

### M-01: Light Visibility Channel追加

- Project Settings / `DefaultEngine.ini` に専用Trace Channelを1本追加。
- `AErasableWall` のSegmentをBlock、DetectionBoxをIgnoreへ設定。
- 既存 `ECC_GameTraceChannel2` の設定は変更しない。

### M-02: 最小ガラス実装

- 既存クラスが無ければ `AColoursGlass` を追加。
- TransmittanceとCollisionだけ実装。
- 見た目の作り込みはしない。

### M-03: 光源基底へ可視性判定追加

- `AColoursLightSourceBase` に非公開/内部ヘルパーを追加。
- `LineTraceMultiByChannel` で候補点までのHitを取得。
- ガラスOverlapを処理し、遮蔽と透過後光値を返す。
- 新しいpublic APIは追加しない。

### M-04: `UpdateErasableWalls()` 接続

- `IsPointLit` だけでセルを消す現行処理を、`IsPointLit + ResolveLightAtPoint` に変更。
- `FColoursLightValue` は透過後値を壁へ渡す。
- SCRUM-20の色一致ゲートはまだ追加しない。

### M-05: 回帰・E2E確認

PIEで以下を確認する。

1. ガラスなし: 従来どおりCone内セルが消える。
2. 通常壁を挟む: 奥の壁へ光が届かない。
3. ガラス1枚: 透過後RGBで奥の壁へ値が届く。
4. ガラス複数枚: 手前から順に透過率が累積する。
5. RGBが黒になる組合せ: その先へ光が届かない。
6. ErasableWallの穴: 消去済みSegment部分から奥へ光が通る。
7. 光源移動・回転: 毎回再計算され追従する。
8. Cone断面表示: SCRUM-73時点の見た目を維持する。
9. `ADynamicErasableWall`: 既存挙動を壊さない。
