- **M-02**: `AErasableWall` が判定目的のコーン固有パラメータを受け取らず、光源側 `IsPointLit` 経由で既存コーン消去が同等動作する。
- **M-03**: 光源が `GetLightBounds` で候補壁を絞り、壁のセル中心を取得して形状判定する責務配置になる。

### Stretch

## 設計方針

### 光源基底の契約

- `virtual bool IsPointLit(const FVector& Point) const`
- `virtual FBox GetLightBounds() const`
- `virtual FColoursLightValue GetLightValueAt(const FVector& Point) const`

形状数学と色の提供は光源派生側へ置く。壁は光源形状を知らない。

### 判定フロー

1. 光源が `GetLightBounds` で `AErasableWall` 候補を絞る。
2. 光源が壁からセル数とセル中心を取得する。
3. 各セル中心を `IsPointLit` で判定する。
4. セルindexと `GetLightValueAt` の値を壁へ通知する。
5. 壁はセル状態を更新する。色照合・消去ゲートは別タスクで接続する。

### レイヤ境界

- 非依存化は判定レイヤだけ。
- `ConeSectionPlug` / `UpdateConeSection` はコーン専用視覚レイヤとして残す。
- `ADynamicErasableWall` 向け既存処理は互換コードとして残し、本Taskでは変更・削除しない。

## 実装手順

### Task 1: 光源基底クラス新設＋契約API定義

- `AColoursLightSourceBase` を `AActor` 派生で新設。
- 3契約APIをvirtual宣言。
- 対象: `ColoursLightSourceBase.h/.cpp`
- 検証: 新規基底だけを追加した段階でビルド。

### Task 2: AColoursConeLightを基底派生へ移行

- 継承元を `AColoursLightSourceBase` へ変更。
- 既存の角度＋距離判定をCone版 `IsPointLit` へ移す。
- Cone版 `GetLightBounds` / `GetLightValueAt` を実装。
- 検証: ビルドと基底経由呼出の静的確認。

### Task 3: AErasableWall本系の判定所有権を移設

- 壁のセル列挙APIを光源側の判定導線へ接続。
- 光源が候補壁を絞り、セル中心を判定してセル状態を駆動。
- 壁の判定用途からコーン固有パラメータ授受を外す。
- `ConeSectionPlug` / `UpdateConeSection` の視覚用途は維持。
- 検証: ビルド、静的責務確認、PIE回帰。

### Task 4: 色passthrough経路

- `GetLightValueAt` の値をセルindexと組にして `AErasableWall` へ通知。
- 色照合・消去ゲートを混入させない。
- 検証: ビルド、型と呼出経路の静的確認、必要なデバッグ確認。
