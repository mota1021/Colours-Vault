# 実装: インタラクト

## 実装方針

### 機能の所有

- プレイヤー側のインタラクトコンポーネントが、インタラクト候補一覧と現在の選択対象を管理する。
- Character Blueprint 側で `UColoursInteractionComponent` を追加し、その直下に `UShapeComponent` 派生（Box / Sphere / Capsule 等）を1つ配置してインタラクト判定範囲として使う。現在は Box を使用する。
- オブジェクト側は `IColoursInteractable` インターフェースを実装する。**インターフェースの有無を「インタラクト候補になれるか」の判定基準とする。**
- 再利用可能なインタラクト時の振る舞いは `UColoursInteractableComponent` 派生として切り出す。1 Actor につき 0 個または 1 個を前提とし、複数所持はサポートしない。
- `UColoursInteractableComponent` がある Actor は、プレイヤー側からそのコンポーネントの `TryInteract` を直接呼ぶ。派生側の具体処理は `PerformInteraction` で実装する。
- `UColoursInteractableComponent` がない Actor は、`IColoursInteractable::Interact` を Actor 自身の BP / C++ で実装して固有処理を行う。
- 選択状態の通知も同様に、コンポーネントがある場合はコンポーネントへ直接通知し、ない場合は `IColoursInteractable::SetInteractionSelected` を呼ぶ。
- 個別の共通インタラクトアクション（拾う等）は、`UColoursInteractableComponent` の派生クラスとして実装する。

### 設定DataAsset

- プレイヤーキャラクターは、プレイヤー全体の設定入口となる **PlayerCharacter DataAsset** を1つ参照する。
- PlayerCharacter DataAsset は、機能別設定として **PlayerInteract DataAsset** をメンバーに持つ。
- 選択切替距離の閾値、閾値境界条件は PlayerInteract DataAsset に保持する。
- `UColoursInteractionComponent` 自体も C++ で生成せず Character Blueprint 側で追加する。
- 判定形状は `UColoursInteractionComponent` の直下に置かれた最初の `UShapeComponent` 派生を使用し、Box / Sphere / Capsule 等へBP上で差し替えられる構造にする。
- 判定形状のサイズ・相対位置・Collision 設定は DataAsset やコードの調整値として持たず、Character Blueprint 上の Shape Component で直接調整する。
- Character は PlayerCharacter DataAsset から PlayerInteract DataAsset の参照を取り出し、プレイヤー側インタラクトコンポーネントへ渡すだけとする。
- PlayerInteract DataAsset の値の解釈・候補選択での利用は、プレイヤー側インタラクトコンポーネントが所有する。
- インタラクト機能は Project Settings の DeveloperSettings から値を取得しない。

### 候補収集

- プレイヤー側の Shape Component 判定範囲に入った Actor のうち、`IColoursInteractable` を実装している Actor を候補一覧へ追加し、範囲から出たら除外する。
- `UColoursInteractableComponent` の有無は候補資格の判定には使わない。
- **候補を集める処理と、候補から選択対象を決める処理は分離する。**

### 選択ロジック

- 現在の選択方式では、候補とPCの距離を比較する。
- 現在の選択対象が有効な間は、別候補が設定した切替距離の閾値だけ近くなった場合にのみ選択対象を切り替える。
- 距離差が閾値と等しい場合の扱いは外部設定で切り替えられるようにする。
- **選択ロジックは独立した処理単位に閉じ込め、候補収集・入力・固有処理側が具体的な優先判定方法へ依存しない構造にする。**
- 将来、距離以外の判定へ変更する場合は、選択ロジックだけを差し替えられるようにする。
- 選択対象が変わったときは、輪郭強調の対象も切り替える。

### 入力

- インタラクト用に独立した `Interact` Input Actionを用意する。
- キーボードでは Fキーを割り当てる。

### 実行とクールタイム

- インタラクト実行時、選択対象に `UColoursInteractableComponent` があれば `TryInteract` を直接呼び、なければ `IColoursInteractable::Interact` を呼ぶ。
- コンポーネント方式では、共通条件確認を `TryInteract`、派生固有処理を `PerformInteraction` に分離する。
- クールタイム制御は `UColoursInteractableComponent` の共通の仕組みを利用する。
- クールタイムの適用条件と時間は各インタラクトコンポーネント側で管理する。
