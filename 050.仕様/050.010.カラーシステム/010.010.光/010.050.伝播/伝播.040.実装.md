# 実装: 光の伝播

## クラス方針

- 伝播（レイ・セグメント・多ホップ・色搬送）を専用の伝播クラス/コンポーネントに集約し、光源（`AColoursConeLight` 等）はそれを呼ぶ。関心分離で、将来の反射・屈折拡張や他光源への再利用に備える（`FColoursColorBase` の static 集約と同じ集約思想）。
- ガラスの表裏を別オブジェクトにする必要はない（GL7解決）。

## 伝播処理

- 現状の単一トレース（`AColoursConeLight::PerformConeTrace()` の `LineTraceSingleByChannel`）を、透過体ヒット時に出射点（裏面）を求めて再トレースするループへ拡張する。
- 出射点（裏面）の求め方など細部の実装手段は実装時おまかせ。
- 一巡単位で、光源から全レイを再計算する（可逆・追従。継続セグメントは永続保持しない。既定N=1のため実質毎tickの再計算と一致）。
- 各ヒット点に、そのレイの色変化後 `FColoursLightValue` を渡すインターフェースを設ける（現状のコーントレースは色を搬送していないため新設）。
- 発射は狙い撃ち方式の2段階（形状の数式判定で候補を絞る→候補へ1本ずつレイ）で行う。ガラス境界でのセグメント分割・再発射はM1で実際に実装する（直進なら1本の直線に畳み込めるが、その近道はしない。将来の反射・屈折の発射駆動フォールバックと同じ骨組みの土台を兼ねる）。

## 形状非依存化アーキテクチャ

- 光源側が提供するもの: ①形状判定「この点は光の中か」（コーン=角度+距離、直線=カプセル内、球=距離のみ。各1関数）②概形バウンズ（対象の壁を絞る用）③色（`FColoursLightValue`）。
- 壁側が持つものはセル分割・各セルの消去状態・復活処理のみで、形状の数学は一切持たない。
- 実現機構は光源基底クラスの仮想関数（ConeLight／BeamLight／FlameSource が各自の形状判定を実装）とし、既存のC++基底クラス方針と地続きにする。

## 判定フロー

1. 光源が範囲内の壁を見つける
2. 壁からセル一覧をもらう
3. 形状判定＋狙い撃ちレイ（広域判定→可視性判定の2段階）
4. 「このセルにこの色が当たっている」と壁へ通知
5. 壁は色一致判定して消去

光センサー・プレイヤー被弾も同じ「点を光源に問い合わせる」インターフェースに乗せ、ギミック追加時に壁側改修が不要になるようにする。

## 外部化パラメータ

- 透過率(T_R,T_G,T_B): ガラス側の既存パラメータ。多ホップ上限は設けない。
- レイ本数は狙い撃ち方式のため候補点数に比例して決まる（手動調整の外部化パラメータではない）。

### 伝播の負荷調整パラメータ（後から調整できるつまみ）

| パラメータ | 現行値/既定 | 効き方 |
|---|---|---|
| 更新周期 | 0.05s | 全体の頻度。上げれば軽く、追従が鈍る |
| グループ数 N | 1 | スパイク平準化。上げれば1回あたり軽く、反映レイテンシN倍 |
