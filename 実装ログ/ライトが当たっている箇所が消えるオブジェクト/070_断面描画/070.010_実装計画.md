## 高レベル手順

1. `AErasableWall` に `ConeSectionPlug`（`UDynamicMeshComponent`）を子コンポーネントとして追加
2. 円錐パラメータ受信時に Transform を同期する `UpdateConeSection()` を追加
3. 壁の AABB でクリップする `M_ConeSection` マテリアル（Custom HLSL）をUEエディタで作成
4. `AColoursConeLight` の push 経路から `UpdateConeSection()` を呼ぶ

## 実装詳細

### 1. コンポーネント構成

```
AErasableWall
├── SceneRoot (USceneComponent) ← RootComponent（底面中心基準）
│   ├── VisualMesh (UStaticMeshComponent)
│   ├── DetectionBox (UBoxComponent)
│   └── ConeSectionPlug (UDynamicMeshComponent) ← SetAbsolute(true,true,true)
```

`ConeSectionPlug` は `SetAbsolute(true, true, true)` でワールド座標固定。親 Actor の移動に引きずられず、`SetWorldTransform` のみが位置を制御する。

### 2. Transform 同期（UpdateConeSection）

| パラメータ | 設定値 |
|---|---|
| 位置 | `LightPos + LightDir * (Range * 0.5)`（コーン中心） |
| 向き | `MakeFromZ(-LightDir)` で -Z を光軸に向ける |
| 母線長（Z スケール） | Range |
| 底面半径（XY スケール） | `tan(acos(CosConeAngle)) × Range` |
| 可視性 | Active と連動 |

> **向き反転の理由**: Engine Cone の apex は local +Z。`MakeFromZ(-LightDir)` で -Z を光軸前方に向けると本体が +LightDir 方向（前方）に開く。

移動壁対応: `Tick`（60fps）で `RefreshConeSection()` を呼びクリップ params とコーン Transform を毎フレーム再計算・再適用。Tick は非アクティブ時 `SetActorTickEnabled(false)` で停止。

### 3. C++ 変更

- `ErasableWall.h/.cpp`
  - `ConeSectionPlug`（UDynamicMeshComponent）+ `UpdateConeSection()` / `RefreshConeSection()` / `RebuildConeSectionPlug()` を追加
  - `ConeSectionRadialSteps`（UPROPERTY, 既定 64, max 1024）で分割数を外部から調整可能
- `ColoursConeLight.cpp`
  - `PerformConeTrace`（20Hz）から `ApplyMIDParams` + `UpdateConeSection` の呼び出しを削除し `Tick`（60fps）に移管（ヒット判定の重処理と視覚更新の頻度を分離）

仕様メモは `AErasableWall` が自分でコーンパラメータを保持する前提だったが、実コードでは `AColoursConeLight` がライブ算出して push する設計のため、`UpdateConeSection()` を public API にして既存の push 経路から呼ぶ形にした。

## マテリアル（M_ConeSection）構築ガイド

### 基本設定

| 項目 | 値 |
|---|---|
| Blend Mode | Masked |
| Two Sided | ON |
| Shading Model | Default Lit |
| Normal | **未接続** |

> Normal は未接続が正解。`TwoSidedSign × (0,0,1) → Normal` は UE の Two Sided 自動反転と二重反転になり内壁が黒くなる。

### VectorParameter 一覧（C++ が実行時に自動セット）

> **名前が1文字でも違うと `SetVectorParameterValue` は黙って何もしない。** `WallHalfExtent` が `(0,0,0)` のまま → 全ピクセル破棄 → コーンが描画されない。

| Parameter Name | C++ が入れる値 | 用途 |
|---|---|---|
| `WallCenterWS` | `GetActorTransform().TransformPosition(FVector(0,0,WallHalfExtent.Z))` | Box clip の原点 |
| `WallHalfExtent` | 壁の半サイズ (X=厚み, Y=幅, Z=高さ) | Box clip の範囲 |
| `WallAxisX` | 壁の Right 方向（ワールド空間単位ベクトル） | 厚み軸 |
| `WallAxisY` | 壁の Forward 方向（ワールド空間単位ベクトル） | 幅軸 |
| `WallAxisZ` | 壁の Up 方向（ワールド空間単位ベクトル） | 高さ軸 |

> `WallCenterWS` が `ActorLocation` でない理由: `AErasableWall` の原点は**底面中心**。箱の幾何中心は底面から `WallHalfExtent.Z` 上にある。

### Custom ノード（OpacityMask へ接続）

```hlsl
float3 d = WorldPos - Center;
float3 local = float3(dot(d, Ax), dot(d, Ay), dot(d, Az));
float3 m = Half - abs(local);
return (m.x > 0 && m.y > 0 && m.z > 0) ? 1.0 : 0.0;
```

**Inputs（6ピン）:**

| Input Name | 接続元 |
|---|---|
| `WorldPos` | `AbsoluteWorldPosition` |
| `Center` | VectorParameter `WallCenterWS` |
| `Half` | VectorParameter `WallHalfExtent` |
| `Ax` | VectorParameter `WallAxisX` |
| `Ay` | VectorParameter `WallAxisY` |
| `Az` | VectorParameter `WallAxisZ` |

Custom ノードの出力 → **OpacityMask** に接続。BaseColor は壁と同色の Constant3Vector を接続。

### デバッグ手順

**症状A — 全く描画されない**
1. OpacityMask を `Constant 1` に差し替えてコーンが見えるか確認。見えない → `ConeSectionMaterial` 割当・ライト稼働確認。
2. VectorParameter 名を上表と1文字ずつ比較。`WallHalfExtent` が `(0,0,0)` → 全ピクセル破棄。

**症状B — 壁の外側まで常時描画される**

`WallAxisX/Y/Z` のいずれかが零ベクトル（内積が常に 0 → 全ピクセルが「内側」判定）。
各 Axis を EmissiveColor に差し替えて PIE で色確認：
- `WallAxisX`（Right ≈ +Y world）→ 緑 (0,1,0) 系
- `WallAxisY`（Forward ≈ +X world）→ 赤 (1,0,0) 系
- `WallAxisZ`（Up = +Z world）→ 青 (0,0,1) 系

黒だったら → ノードが `Constant3Vector` になっている。右クリック → **Convert to Parameter** → 正しい名前を設定。
