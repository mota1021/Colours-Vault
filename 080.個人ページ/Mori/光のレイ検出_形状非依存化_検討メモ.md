# 光のレイ検出方式・光源形状非依存化 検討メモ

## Context（何を決めたか）

コーンライトのレイ検出（現行: 水平扇のライントレース7本）を良くしたい、という起点から、
以下4論点を設計討議し方式を確定した。**成果物は本メモまで**（仕様書更新・実装計画は別セッション）。

1. レイ配置方式（放射状化と「距離が離れるほど判定が粗くなる」問題への対処）
2. レイの色・強さ搬送の負荷
3. 更新の分散（レイのグループ分割）
4. ErasableWall の消去判定の光源形状非依存化（コーン／直線／球）

### 要件（Phase 1 で合意）

- 光型 RGB(正規化)+Intensity+DamageValue と伝播仕様（レイ単位・色搬送・多ホップ・毎回再計算・可逆追従）は既決。矛盾しないこと
- ビーム（直線）・炎（球）は**判定方式の設計まで**。ギミック仕様書は作らない
- 精度: 多少の粗さ許容（遠距離でセル1個程度の取りこぼし・ちらつきOK）
- 負荷: 体感基準（フレーム落ちを体感しない）。レイ本数・更新頻度は後から調整可能な設計にする

### 現状の前提事実

- 消去判定は既にレイではなく「セル中心がコーン体積内か」の数式判定（3×8×4=96セル、実装ログ 020.060）。
  コーン前提は**壁側の判定式**に埋まっている
- レイ（水平扇）は実装ログ 020.020 の `PerformConeTrace()`、タイマー周期 0.05s
- 「距離が離れると判定が粗くなる」のは放射状レイ**だけ**で判定しようとした場合に生じる問題。数式判定は距離によらず厳密

## 論点1: レイ配置方式 → 「形状の数式判定＋狙い撃ちレイ」の2段階（採用）

1. **広域判定（形状）**: 壁の各セル中心が光の形状体積（コーン／直線／球）内かを数式で判定し、候補セルを絞る
2. **可視性判定（レイ）**: 候補セルにだけ、光源→セル中心へ1本ずつレイを撃つ。
   途中に遮蔽物があれば当たっていない。途中がガラスなら乗算モデルで色変換し、変換後の色でセルに到達

**採用理由**:
- 疎化問題が構造的に消滅（レイは必要な場所へ正確に飛ぶ。本数は照らされているセル数に比例し、距離に比例しない）
- 遮蔽（間に物を置いたら影になる）が放射状より正確
- ガラス多ホップは「光源→セルの1本のレイが途中のガラスで色を乗算しながら進む」として自然に実現
  （反射・屈折なしの現仕様では直進なので伝播仕様と等価）

**不採用案**: A=放射状レイのみ（疎化が原理的に残り、遠端解像度に数百本必要）／C=適応分割放射（複雑度過剰）

**制約**: 受け手が列挙可能である必要がある（壁=セル、センサー=判定点、プレイヤー=代表点。現行ギミックはすべて満たす）

**追加決定（2026-07-11 討議続き）**: ガラス境界での**セグメント分割・再発射は M1 でも実際に実装する**
（直進なら1本の直線に畳み込めるが、その近道はしない）。将来の反射・屈折で必要になる
発射駆動フォールバック（後述「将来検討」）と同じ骨組みの土台を兼ねる。

## 論点2: レイの色・強さ搬送 → 各レイが光値＋残射程を持つ（採用・負荷は心配不要）

- レイ1本の処理＝「色コンテキスト（FColoursLightValue＋残射程）を持ってトレースし、ガラス通過ごとに乗算」
- 搬送データは float 5個（約20バイト）、透過計算は乗算3回＋正規化程度。
  物理レイキャスト自体のコスト（1本あたり数μs）が支配的で、色の搬送・計算は無視できる
- レイは毎回再計算で永続保持しない（伝播仕様どおり）ため、メモリ蓄積もない
- 負荷の懸念はレイの**本数**のみであり、論点1（本数=照射セル数比例）と論点3（分散）で制御する

## 論点3: 更新の分散 → グループ分割＋一巡後一括反映、既定N=1（採用）

- 候補セルを N グループに分け、1回の更新で1グループだけトレース。
  **一巡完了時に結果を一括反映**（ダブルバッファ。虫食いの中間状態を見せない）
- **グループ数 N はパラメータ化し、既定 N=1（＝分散なし）で開始**。実測で重ければ N を上げるだけで平準化へ移行
- 反映レイテンシは N倍（N=3・周期0.05sなら0.15s）。精度要求「多少の粗さ許容」の範囲内

### 復活ルール（めり込み・潜り込み対策、討議で確定）

危険なのは「復活（コリジョン有効化）」の方向のみ。消去の遅延は安全側。
この危険は N の値と無関係で、N=1 でも現行実装でも存在する（Step6.1 めり込みバグとして既に顕在化）。

- 単純な「重なり中は復活保留」は**不採用**: 動く光源の穴を追いかけて壁内部に居座り続け、
  壁を丸ごとすり抜ける抜け道（パズル崩壊）になるため
- **採用: 押し出し＋最終手段リスポーン**
  - 復活領域にキャラ・物体が重なっていたら、最も近い空き空間（消えている穴の方向・壁の外側面）へ押し出してから復活
  - 押し出せない場合のみ、圧殺扱いでダメージ／リスポーン

### 押し出しの安全規定（ふっとび・振動対策、討議で確定）

1. 押し出しは「セル単位」ではなく**キャラ・物体単位で1回**。その更新で復活したい全セル
   （複数の壁・複数の光源にまたがっていても）を1つの復活領域（合算）として扱い、押し出し先と量を1回だけ算出
2. **速度を与えない位置補正**として実行（物理インパルス禁止）。押し出し後の速度は押し出し方向成分をゼロにクランプ
3. 移動はコリジョンを尊重した**スイープ移動**で行い、押し出した先が別の壁の中にならないようにする
4. **押し出し距離に上限**を設け、超過時（深く埋まりすぎ）は「押し出し不能」とみなしてダメージ／リスポーン側へ倒す

※「一巡後一括反映」により復活が一巡ごとの1タイミングに同期されるため、「アクター単位で合算して1回解決」が
自然に書ける（セルがバラバラのtickで復活する方式だと毎tick少しずつ押される階段状のガタつきが避けにくい）。

## 論点4: 形状非依存化 → 形状の数学は光源側、壁はセルと消去状態のみ（採用）

- **光源側**が提供するもの:
  1. 形状判定「この点はあなたの光の中か」（コーン=角度+距離、直線=カプセル内、球=距離のみ。各1関数）
  2. 概形バウンズ（対象の壁を絞る用）
  3. 色（FColoursLightValue）
- **壁側**が持つもの: セル分割・各セルの消去状態・復活処理のみ。形状の数学を一切持たない
- 実現機構: 光源基底クラスの仮想関数（ConeLight／BeamLight／FlameSource が各自の形状判定を実装）。
  既存の C++ 基底クラス方針と地続き
- 判定の流れ: 光源が範囲内の壁を見つける → 壁からセル一覧をもらう → 形状判定＋狙い撃ちレイ（論点1）
  → 「このセルにこの色が当たっている」と壁へ通知 → 壁は色一致判定して消去
- 光センサー・プレイヤー被弾も同じ「点を光源に問い合わせる」インターフェースに乗るため、
  ギミック追加時に壁側改修が不要

## 将来検討: 反射・屈折が入った場合の結線判定（素描・先送りで確定）

反射・屈折は予定どおり先送り（Stage1スコープ外）。ただし狙い撃ちレイ方式は
「光源と受け手を直線で結べる」ことに依存するため、曲がる光をどう判定するかの方向性だけ記録しておく。

**統一観点**: 多ホップを「レイ単位のホップ」から「**光源単位のホップ**（実光源→派生光源のチェーン）」に
持ち上げる。受け手側は問い合わせ先の光源リストが増えるだけで、論点1・4の骨組みは変わらない。

**枝刈り（受け手はどの光源を計算すべきか問題）**: 受け手は光源を探さない（論点4の光源駆動を維持）。
- 屈折・反射は決定論（スネル則・鏡映）なので「届き得る領域」は幾何で囲える。一次体積が界面と
  **実際に交差したときだけ**、屈折後/反射後の**派生体積**（境界レイを屈折/鏡映して作る凸近似、保守的に膨張。
  水中側は臨界角約49°以内・残射程でも有界）をイベント駆動で生成する
- 派生体積も「1個の光源」として振る舞い、自分のバウンズ内の壁・セルだけを候補化 → 候補セルにのみ
  折れ点解法＋2区間遮蔽レイの狭域判定（保守的な派生体積の誤検出はここで落ちる）
- 見当違いの方向を向いたライトは界面と交差せず派生体積を生まないため、無駄計算は構造的に発生しない。
  スケールするコストは派生体積の個数（＝光×界面の実交差数、ホップ上限パラメータで制御）のみ

| ケース | 方式 | 備考 |
|---|---|---|
| 反射（平面鏡） | **鏡像法**: 光源Sの鏡像S′を作り、線分S′–Pと鏡面領域の交点Qを求め、S→Q・Q→Pの直線2区間で遮蔽レイ | 折れ点は幾何で一発。鏡像コーン＝派生光源。多重反射は鏡像チェーン（回数上限をパラメータ化）。曲面鏡には使えない |
| 屈折（平行平板ガラス） | **直線近似のまま**: 出射が入射と平行で横オフセットのみ。薄ければ無視、厚ければ閉形式の補正項 | 板ガラスだけなら先送りのまま実質カバー済み |
| 屈折（空気→水の平面界面） | **受け手ごとの折れ点解法**: 対称性から折れ点Qは水面上の1次元位置に落ち、スネル条件 f(x)=sinθ₁−n·sinθ₂ が単調なので二分法/ニュートン法で3〜5回反復で一意に解ける（純算術・レイ不要）。求めたQで直線2区間の遮蔽レイ | **固定の仮光源は厳密には存在しない**（見かけの位置が観測角度で動く＝屈折像は1点に結ばない）。仮光源が使えるのは近軸近似（見かけの位置に1個置く。斜めほど誤差拡大、「多少の粗さ許容」なら可）としてのみ。逆方向（水中→空気）は全反射があり「経路が存在しない」判定が追加で必要。広域判定は保守的な近似体積で拾い、折れ点解法で正確に絞る2段構え |
| 屈折（曲面・プリズム・波打つ水面） | **発射駆動ハイブリッド**: 屈折体の出射側でセグメント束を再発射し「屈折後の光場」＝派生光源を作る。受け手はセグメント束への近接判定または近似体積への問い合わせ | 閉形式で結べないため。疎化問題が再登場するが、起点が屈折体の出口なので被害は局所ギミック単位に閉じる。M1で実装するセグメント再発射と同じ骨組み |
