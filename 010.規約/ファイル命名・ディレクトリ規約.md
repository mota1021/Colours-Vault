# ファイル命名・ディレクトリ規約

Colours プロジェクトのドキュメント（Vault 内）に適用する命名・構成ルール。
コード/アセットの命名は対象外（→ [[コーディング規約]] / [[アセット命名規約]]）。

---

## 1. 基本方針

- **「読み順・優先順に意味があり、項目が増えていく」カテゴリは番号を振る**（例: 仕様、実装ステップ、ステージ）。
- **辞書的に名前で引くもの・固有名・時系列ログは番号を振らない**（例: 規約集、人物ページ、日次ログ）。
- 1ディレクトリ＝1カテゴリ。階層はディレクトリで表現する。
- `_` プレフィックスは**原則禁止**。番号または内容を表す名前を使う。**テンプレートファイル・テンプレートディレクトリは例外**（`_` を付けてファイラ上部にまとめる）。

---

## 2. 番号フォーマット（番号を振るカテゴリ）

- **3桁**。1の位はバッファとして `0` 固定 → `010, 020, 030 …`（10刻み。間に挿入余地を残す）。
- 100 を超える規模になったら、それはカテゴリ分割のサイン → サブディレクトリを切る。
- **階層番号は最大2段**：子は `[直近親の末尾番号].[自番号]`。孫以降も直近親1つ分まで連結し、それ以上はつなげない。フォルダ内で一意であれば十分。
  - 例: `040.020.ライト機能/` の子ステップ `040.020.ライト機能/020.020.ライントレース検知/`、その中の別文書 `070.010.実装計画.md`（親番号 `040.020` の子なので `070.010`）。
- **フォルダノート（ディレクトリ概要）は `[意味名].000.index.md`**（→ §2.1）。役割番号 `000` で常にフォルダ先頭へソートされ、basename が意味名始まりのため Obsidian のタブ・グラフ・検索・wikilink で識別しやすい。
- 区切り文字：番号と名前の間・階層番号間ともに `.`（ドット）。

**例**（ディレクトリの番号。配下ファイルの命名は §2.1 参照）
```
050.仕様/                               ← shared/ 直下の番号 050
  050.000.概要と規約.md                  ← 仕様ルート索引（050の子 → 050.000）
  050.010.カラーシステム/
    カラーシステム.000.index.md          ← カテゴリ索引（CMY型定義・共通概念）
    010.010.光/
      光.000.index.md
      光.020.仕様.md
  050.020.プレイヤー/
    プレイヤー.000.index.md
    020.010.モノを拾う/                  ← 孫：直近親 050.020 の末尾 020 → 020.010
      モノを拾う.000.index.md
      モノを拾う.020.仕様.md
  050.030.ギミック/
    030.010.ライト/                    ← 孫：直近親 050.030 の末尾 030 → 030.010
      ライト.000.index.md
      010.010.懐中電灯/               ← 曾孫：直近親 030.010 の末尾 010 → 010.010
        懐中電灯.000.index.md
        懐中電灯.020.仕様.md
      010.020.サーチライト/
```

## 2.1 仕様ファイルの命名（`050.仕様/` 配下）

**形式: `[意味名].[役割番号].[役割].md`**（例: `モノを置く.020.仕様.md`）

- **意味名** = 自フォルダ名から `NNN.MMM.` の番号 prefix を除いた部分（`020.020.モノを置く/` → `モノを置く`）。
- **役割番号・役割** は 5ファイル構成で固定（`000.index` / `010.ラフ` / `020.仕様` / `030.演出・UI` / `040.実装`）。役割の詳細は [[050.000.概要と規約]] が正本。
- ディレクトリ名は §2 の階層番号ルールのまま（**フォルダ名は番号付き・ファイル名は意味名始まり**）。

**なぜ意味名を前置するか**: Obsidian の wikilink は basename で解決するため、`020.020.仕様.md` のような番号のみの名前では Vault 内で大量に衝突し、どの仕様を指すか特定できない。意味名を前置して **basename を Vault 内で一意**にすることで `[[モノを置く.020.仕様]]` という読める wikilink が使える。

**制約**:
- **意味名は Vault 内で一意にする。** 新規仕様のフォルダを切る際に既存の意味名と重複しないか確認する（`/colours-spec-interview` の手順に組み込み済み）。
- **意味名に `.`（ドット）を使わない。** 役割番号の区切りと衝突してファイル名がパースできなくなる。
- 同じく `/ \ : # ^ [ ] |` も使わない（パス・wikilink 構文と衝突する）。
- 役割番号を残しているため、フォルダ内は `000 → 040` の役割順にソートされる。

## 3. 特殊ファイル

### テンプレートファイル
- 雛形：`_[名前]_template.md`（先頭 `_` でファイラ上部にまとめる）
- input 雛形：`_[名前]_input_template.md`
- テンプレートディレクトリ：`_template/`
- 新規作成時にコピーして使う。中身を直接編集しない。

### input / output 2ファイル運用
確定文書（Claude整形）とラフ（ユーザー記入）を分離する。

| 種別 | ファイル名 | 誰が書くか |
|---|---|---|
| output（確定） | `[名前].md` | Claude が整形 |
| input（ラフ） | `[名前]_input.md` | ユーザーが気軽に |

### 日付サフィックス
時系列で量産されるログは `[名前]_YYYYMMDD.md`（番号は振らない）。

### 実装ログの日付 prefix（070.040.実装ログ/ 専用）
実装ログは **1作業1ファイル**、日付を先頭に置く `YYMMDD.<作業名>.md` 形式を使う。
- `YYMMDD` = 着手開始日（6桁）
- 終了日はファイル内 frontmatter に記載。
- 変更したくなったら別作業として新ファイルを作る（上書き禁止）。
- 既存の番号付きログ（`040.020.xxx/` 以下）はそのまま残す（移行しない）。

## 4. ディレクトリ別 適用方針

| ディレクトリ | 番号 | 命名ルール |
|---|---|---|
| `shared/` 直下 | ◯ | ファイル・ディレクトリ混ぜて一本読み順（010〜080）。`070.040.開発/` に進行管理・実装ログを集約。`999.アイデアプール.md` 末尾固定 |
| `050.仕様/` | ◯（ディレクトリのみ） | ディレクトリ: 3桁・最大2段番号（`050.xxx`）。**ファイル: `[意味名].[役割番号].[役割].md`**（→ §2.1） |
| `070.開発/070.040.実装ログ/` | — | **新規ログ**: フラット・`YYMMDD.<作業名>.md`・1作業1ファイル（→ §3「実装ログの日付 prefix」参照）。**既存の番号付きログ**（`040.020.xxx/` 以下）は据え置き。テンプレートは `_template/` |
| `060.level_design/` | ◯ | ステージは `060.level_design/060.010.Stage1/`、プロトタイプは `060.level_design/060.000.プロトタイプ/` 等。テンプレートは `_` プレフィックス |
| `010.規約/` | ✕ | 内容を表す名前（`〜規約.md` `〜フロー.md`） |
| `080.個人ページ/` | ✕ | 人名ディレクトリ。テンプレートは `_template_member/` |
| `個人計画/` | ✕ | 索引・計画は名前、日次/週次ログは日付サフィックス。テンプレートは `_テンプレート/` |

## 5. 改名の手順

リネームは手動編集せず**スクリプトで一括変換**し、wikiリンク・パス参照も同時更新する。
実施後は git＋Diversion 両方へコミット。

> 実績：
> - `shared/仕様/` 命名規則統一（2026-06-24 / commit `1c7b697`）

> - フォルダノート同名化・番号2段化・テンプレート`_`化（2026-06-24 / commit `79cc067`）
> - `shared/` 直下への番号付与・`070.開発/` 新設（2026-06-24 / 本コミット）
> - 番号区切り `_` → `.` 統一・カラーシステム構造追加（2026-06-26）
> - 実装ログを `YYMMDD.<作業名>.md`（フラット・日付prefix）方式へ変更（2026-06-28）
> - 仕様ファイルを `[意味名].[役割番号].[役割].md` へ刷新し basename を一意化・wikilink化（2026-07-15）
