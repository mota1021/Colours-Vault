# Colours — コーディング規約

> UE公式C++コーディング標準に準拠する。
> 参考: https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine

---

## 命名規則

| 種別 | プレフィックス | 例 |
|---|---|---|
| Actor派生クラス | `A` | `AColourLight` |
| UObject派生クラス | `U` | `UColourComponent` |
| 構造体 | `F` | `FColourData` |
| Enum | `E` | `EColourType` |
| Interface | `I` | `IInteractable` |
| テンプレート | `T` | `TArray` |
| 変数・関数 | PascalCase | `LightIntensity`, `GetColour()` |
| ローカル変数 | PascalCase（UE標準） | `LocalValue` |
| bool変数 | `b` プレフィックス | `bIsActive` |

## UPROPERTY / UFUNCTION

- `Category` 指定を必須とする（Detailsパネルで探しやすくするため）。
- Blueprintに公開する場合は `BlueprintReadWrite` / `BlueprintCallable` を明示する。

```cpp
UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Colour")
float LightIntensity;

UFUNCTION(BlueprintCallable, Category = "Colour")
void ApplyColour(EColourType InColour);
```

## コメント規約（Doxygen）

- **配置**: 関数の Doxygen コメント（`@brief` / `@param` / `@return` 等）は**定義側（.cpp）**に書く。宣言側（.h）には書かない。
- **仕様ポリシーの新設禁止**: コメント（`@note` 等）で仕様上の判断・ポリシーを新たに決めて書かない。仕様の正本は仕様書（`shared/050.仕様/` の 020.仕様 / 030.演出・UI / 040.実装）。実装中に未決仕様が見つかった場合はコメントに書かず、ユーザーに確認する。

## コミットメッセージ規約（Conventional Commits）

```
<type>(<scope>): <概要>
```

| type | 用途 |
|---|---|
| `feat` | 新機能追加 |
| `fix` | バグ修正 |
| `refactor` | 動作変更なしのリファクタ |
| `docs` | ドキュメントのみの変更 |
| `chore` | ビルド・設定・依存関係の変更 |

例:
```
feat(EW): 壁消去のフェードアウト演出を追加
fix(CS): 混色判定のしきい値が0の場合にクラッシュする問題を修正
docs(vault): コーディング規約を追加
```
