## 現在の主対象

**携帯ライトの拾得・設置**

- M2 の次のプレイヤーループとして、携帯ライトを拾い、壁へ向けて床に置ける状態を成立させる。
- 設置後も点灯を維持し、置いた向きを保って照射し続けることが必要。

### 2026-09-21 インタラクト基盤完了

- インタラクト候補検出を、DynamicMesh のコーン + Complex Collision 方式から、Character Blueprint 上で配置する Shape Component 方式へ変更した。現在の判定形状は前方 Box。
- `UColoursInteractionComponent` は Character Blueprint 側で Add Component し、直下の `UShapeComponent` 派生を判定範囲として使用する。Box / Sphere / Capsule 等へBP上で差し替え可能。
- 判定形状のサイズ・相対位置・Collision 設定はBP上の Shape Component で直接調整し、コードや DataAsset の調整値としては持たない。
- 複数候補の優先判定はPCからの距離を基準とし、選択切替のヒステリシスを維持する。
- `IColoursInteractable` は「Actor がインタラクト候補になれる資格」、`UColoursInteractableComponent` は「インタラクト時の再利用可能な振る舞い」として責務を分離した。
- `UColoursInteractableComponent` は 1 Actor につき 0 個または 1 個を前提とする。
- Component がある場合はプレイヤー側から `TryInteract` を直接呼び、Component がない場合だけ Actor 側の `IColoursInteractable::Interact` を呼ぶ。
- PIEで `BP_TestInteractable` が候補・選択対象になり、F入力から `BPC_TestInteract::PerformInteraction` まで到達して動作することを確認済み。
- Componentなし・InterfaceのみのActor固有 `Interact` 経路は未確認。M2の次工程をブロックしないため、インタラクト基盤タスクの完了条件外として残す。
- Jira のインタラクト基盤タスクは「完了」へ更新済み。
- UEColours は今後、原則として `master` へ直接 commit する。PR は明示的なレビュー等が必要な場合のみ使用する。

### 2026-09-20 終了地点

- インタラクト仕様を更新済み。
  - プレイヤー追従のコーン型判定範囲内を候補とする。
  - 候補間の優先判定は距離基準。
  - 選択切替にはヒステリシスを使用し、閾値と境界条件を調整可能にする。
  - インタラクト入力は F キー。
- プレイヤー側インタラクト基盤を UEColours に実装済み。
  - 候補収集と選択ロジックを分離。
  - 選択ロジックは差し替え可能な構造。
  - `IColoursInteractable` の共通窓口を追加。
  - 選択対象1つだけへ強調通知を送る。
- プレイヤー設定は Project Settings ではなく DataAsset 階層へ変更済み。
  - PlayerCharacter DataAsset をプレイヤー設定の入口とする。
  - そのメンバーとして PlayerInteract DataAsset を参照する。
  - コーン範囲、ヒステリシス閾値、境界条件は PlayerInteract DataAsset に保持する。
- UEColours PR #5「インタラクト基盤: コーン候補検出と距離ヒステリシス」は master へマージ済み。
  - merge commit: `b8e0d0e601a4cd3784e41141da266a649591af4b`
- 現段階では、Fキーで共通 `Interact` を呼び出す基盤まで。
  - オブジェクト側の共通インタラクトコンポーネントは未実装。
  - 「拾う」固有コンポーネントは未実装。
  - 携帯ライトを実際に拾って所持状態へ移す処理は未実装。
